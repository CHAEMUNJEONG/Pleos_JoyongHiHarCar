# JoYongHiHarCar 개발 계획

기준일: 2026년 11월 15일

JoYongHiHarCar는 대화·후진·동승자 휴식 상황에 맞춰 현재 재생 중인 차량 미디어의 음량과 소리 위치를 조절하는 서비스를 목표로 합니다. 현재는 오디오 조절을 가상 값으로 보여 주는 네이티브 시연 앱과 정책 엔진을 구현했습니다. 다음 개발의 핵심은 제조사 승인을 받은 실제 오디오 연동과 차량 환경에서의 발화 감지 검증입니다.

이 문서는 완료된 개발과 앞으로 필요한 개발을 구분합니다. 제조사 권한·API 계약·시험 차량이 확보되지 않은 기능은 실차 구현 완료로 간주하지 않습니다.

## 1 서비스 범위

| 기능 | 최종 목표 | 공통 원칙 |
| --- | --- | --- |
| 대화 시 감소 | 운전자와 동승자의 발화를 감지해 차량 미디어 음량을 낮추고 종료 후 복원 | 전사·대화 저장 없이 활동 여부만 판단 |
| R단 진입 시 감소 | 주차 경고음 발생 여부와 무관하게 기어 R 진입 자체로 미디어 음량 감소 | R 해제 후에도 다른 조건이 남으면 낮은 음량 유지 |
| 나만 듣기 | 사용자가 직접 선택하면 운전석 쪽으로 페이더·밸런스 이동 | 자동 수면 감지나 완전한 차음으로 소개하지 않음 |
| 조건·수동 조작 관리 | 조건이 겹쳐도 한 번 계산하고, 사용자의 수동 변경을 우선 | 정상 해제 시 앱이 소유한 값만 복원 |

제어 대상은 우리 앱의 플레이어에 한정하지 않고 차량에서 재생 중인 미디어입니다. 안전·주차 경고음과 필요한 내비게이션 안내를 함께 낮추지 않도록 오디오 그룹의 분리 여부를 확인해야 합니다. 음악 스트리밍 서비스, 메모·캘린더, 대화형 AI는 범위에 포함하지 않습니다.

## 3 기술 구성과 API 사용 계획

### 앱과 정책

공식 Android/Pleos 연동을 위해 현재는 Java 네이티브 구성을 사용합니다. AudioPolicy가 시간과 활성 조건으로 목표 음량을 계산하고, PositionPolicy가 페이더·밸런스의 축별 소유권을 관리합니다. AutomationService가 마이크·기어 입력과 정책 실행을 직렬화하며, MainActivity는 실제 연동과 화면 시연을 구분해 표시합니다.

화면 시연은 가상 값만 변경하는 별도 경로입니다. 실제 어댑터는 권한과 능력이 확인될 때만 사용합니다. 실제 API가 제공되지 않는 기능을 자체 음악 플레이어 음량으로 바꾸거나 권한 상승 방식으로 구현하지 않습니다.

### 기어

기어 읽기는 표준 AAOS CarPropertyManager와 GEAR_SELECTION을 사용합니다. CAR_POWERTRAIN은 읽기용 normal 권한이며, 기어 제어용 CONTROL_CAR_POWERTRAIN은 사용하지 않습니다. 유효한 최초 값과 변경 이벤트를 모두 처리하고, 읽기 불가를 R단 해제로 가정하지 않습니다.

### 차량 미디어 음량

제조사와 CAR_CONTROL_AUDIO_VOLUME 권한 및 지원 오디오 그룹을 협의합니다. 승인 후 USAGE_MEDIA가 속한 그룹의 현재·최소·최대 음량, 쓰기 결과, 수동 변경 이벤트를 확인합니다. 내비·안전 관련 usage와 그룹이 공유되면 자동 조절을 차단합니다. 단순 권한 선언을 승인으로 간주하지 않습니다.

### 페이더와 밸런스

CAR_CONTROL_AUDIO_SETTINGS 승인뿐 아니라 적용 전 값을 신뢰할 수 있게 읽는 방법, 운전석 방향·좌석 배치, 쓰기 결과 확인, 외부 수동 변경 통지가 필요합니다. 원본 값을 읽거나 수동 변경을 구분할 수 없다면 실제 ‘나만 듣기’를 활성화하지 않습니다. 각 축의 소유권은 별도로 관리합니다.

### 마이크와 감지

사용자가 화면에서 기능을 켜고 RECORD_AUDIO를 허용하면 microphone foreground service를 시작합니다. PCM은 메모리에서만 처리하고 파일·전사·서버 전송을 만들지 않습니다. 향후 차량 마이크 경로와 AEC 참조 신호 제공 여부를 협의해 재생음의 오인을 줄입니다. 기기의 AEC/NS 지원은 런타임에 확인하며 제공되지 않는 효과가 있는 것처럼 표시하지 않습니다.

## 4 단계별 개발과 완료 기준

아래 순서는 후속 개발의 실행 단계입니다. 확정된 출시일이나 제조사의 승인 일정을 뜻하지 않습니다. 단계 1의 API 계약과 시험 장비가 확보된 뒤 상세 일정을 산정합니다.

| 단계 | 주요 개발 | 산출물 | 완료 기준·진입 조건 |
| --- | --- | --- | --- |
| 0 현재 기반 | 시연 앱, 정책, 에뮬레이터 기어 읽기, 실험용 마이크 | 소스, release APK, 시연 가이드와 검증 기록 | 현재 기록된 자동 검증·터치 시연 통과. 물리 오디오 완료와 구분 |
| 1 연동 조건 확정 | 제조사와 오디오 권한·그룹·위치 읽기/복원·마이크 경로 협의 | 권한 목록, 지원 API·능력 표, 대상 차량·에뮬레이터 명세 | 미디어와 안전음 분리, 수동 변경 통지, 원본 위치 읽기 지원 여부를 확인 |
| 2 승인 환경 오디오 통합 | 기존 프로토타입 브리지를 승인 환경에서 검증·완성. 실제 쓰기 반영, 수동 변경 감지, 실패·권한 회수 처리 강화 | 승인 환경에서 검증한 음량 어댑터와 장치 시험 | 다른 앱 미디어 제어, 경고/안내 그룹 비개입, 수동 변경 보존, 권한 회수·연결 단절 처리 확인 |
| 3 운전석 집중 연동 | 원래 페이더/밸런스 보관·적용·축별 복원 | 실제 소리 위치 어댑터 | 원본 읽기·쓰기·외부 변경 식별 가능. 모드 해제·중지·재개 후 사용자가 바꾼 축 보존 |
| 4 발화 감지 개선 | 차량 마이크·AEC 참조, 잡음 대응, 시작/종료 안정화 | 평가 데이터 조건표와 감지 성능 보고서 | 좌석·음악/라디오/내비·주행 소음 조건별 오인과 누락, 시작 지연·종료 지연을 측정. 측정 후 수용 목표 확정 |
| 5 통합·실차·배포 검증 | 복합 상황, 장시간 실행, 전환·오류 복구, 차량 심사 | 검증 보고서, 심사용/배포용 APK, 사용자 안내 | 승인된 권한 범위, 실차 반복 시험, 개인정보 처리와 서명·배포 요구사항 확인 |

단계 4의 측정 환경 설계는 단계 1과 함께 준비할 수 있지만, 전체 좌석·차종의 정확도를 미리 보장하지 않습니다. 실제 녹음이 필요한 별도 평가를 하게 된다면 앱의 무저장 기본 동작과 분리하고 시험 참여자의 동의·보관 범위를 먼저 정합니다.

## 5 기본 음량 정책과 시연 수용 기준

| 항목 | 현재 기본값·동작 | 확인할 결과 |
| --- | --- | --- |
| 대화 감소 | 65% 감소, 잔여 35%, 감소 램프 0.4초 | 가상 기준 28에서 약 10 |
| 후진 감소 | 75% 감소, 잔여 25%, 감소 램프 0.4초 | 가상 기준 28에서 7 |
| 대화+후진 | 더 강한 감소율 한 번 적용 | 28 × 25% = 7, 두 이유 표시 |
| 대화 종료 | 침묵 3.0초 + 추가 대기 0.5초 + 복원 램프 1.8초 | 다른 조건이 없으면 약 3.5초부터 상승, 약 5.3초에 기준 복원 |
| R → P | 해제 유지 1.2초 + 추가 대기 0.5초 + 복원 램프 1.8초 | 다른 조건이 없으면 약 1.7초부터 상승, 약 3.5초에 기준 복원 |
| 대화 재개·R 재진입 | 진행 중 복원을 취소하고 활성 조건 재계산 | 기준 음량으로 갑자기 올리지 않음 |
| 수동 볼륨 | 현재 상황이 끝날 때까지 자동 개입 양보 | 이전 기준으로 강제 복원하지 않고 다음 상황부터 새 기준 사용 |
| 위치 수동 변경 | 축별 자동 소유권 해제 | 직접 바꾼 축은 해제·중지·재개 이후에도 보존 |

수치는 화면 시연과 코드 기본값 기준입니다. 실제 마이크의 종료 판정에는 약 0.6초가 더 걸릴 수 있습니다. 현재 일반 APK가 그 신호로 실차 음량을 복원하는 것은 아니며, Android 처리 주기와 반올림에 따라 화면 시점도 조금 달라질 수 있습니다.

## 6 검증 계획

### 정책과 통합 회귀

기존 80개 정책 assertion과 26개 서비스 통합 check를 유지합니다. 실제 어댑터 연결 후에는 음량 최소값이 0이 아닌 그룹, 쓰기 지연·실패, 수동 조작과 자동 램프의 충돌, R 반복 전환, 대화 중 R 해제와 R 중 대화 종료, 마이크 권한 회수, 연결 단절을 추가 검증합니다. 복원 전에 최신 수동 조작과 남은 조건을 확인합니다.

### 발화 감지 평가

운전석·조수석·뒷좌석의 발화, 문장 사이 침묵, 재생 음악 보컬, 라디오 진행자, 내비 안내, 비언어 소음, 주행 소음 조건을 나누어 시험합니다. 발화 검출률·누락률·시간당 오인 횟수·검출/종료 지연을 기록합니다. 현재 단순 활동 감지와 개선 방식은 같은 조건으로 비교하고, 원시 대화 보관 없이 가능한 통계부터 수집합니다.

### 실제 오디오와 복원

우리 앱 밖의 미디어·라디오가 제어되는지, 경고/안내 그룹의 음량을 쓰지 않는지, 사용자가 설정한 음량·위치가 보존되는지를 각각 확인합니다. 정상 중지에는 소유 중인 값만 복원합니다. OS 강제 종료·전원 차단·통신 단절에서는 복원을 보장할 수 없으므로 실제 장치의 안전한 실패 동작과 사용자 안내를 점검합니다.

## 7 진행 판단 기준

- 승인된 미디어 제어 권한을 얻지 못하면 화면 시연과 감지·기어 읽기 단계로 유지하고 지원 범위를 명시합니다.
- 신뢰할 수 있는 위치 읽기·수동 변경 통지가 없으면 실제 페이더/밸런스 모드를 제공하지 않습니다.
- 재생음 오인과 좌석별 검출 성능을 측정하기 전에는 완성형 실차 대화 감지로 소개하지 않습니다.
- 공개 저장소에는 소스·APK·시연·개발 문서를 제공합니다. 연락처·서명·동의 내용이 포함된 공모전 신청서 원본과 수정본, 로컬 서명 키는 포함하지 않습니다.
